# Project Map

This file documents the structure and key components of the Nuxt 4 portfolio project. **Every structural change or new functionality added MUST be documented here.**

## Core Setup

- **Framework:** Nuxt 4 + Vue 3 + TypeScript
- **Styling:** Tailwind CSS + SCSS (`assets/scss/base.scss`)
- **Typography:** `@nuxt/fonts` self-hosts **Geist** (display + body sans, full weight range) and **Geist Mono** (code). Global type scale lives in `nuxt.config.ts` under `tailwindcss.config.theme.extend.fontSize` as fluid `clamp()` tuples with `lineHeight` + `letterSpacing`. Display sizes use the `text-d-*` utilities (`d-xs`…`d-2xl`). Body defaults to `font-sans`; headings auto-apply `font-display font-semibold tracking-tight` + `text-wrap: balance` via `@layer base` in `base.scss` (H1 is `font-bold`). Section rhythm tokens: `p-section-y`, `p-section-x`, `gap-gutter`; content widths: `max-w-prose`, `max-w-content`. Title + subtitle pairs use a `<header>` wrapper (single external `mb-*`, internal `mt-3` between H2 and `<p>`) — applied in `TechStack.vue` and `Contact.vue`.
- **State:** Pinia (`stores/theme.ts`)
- **i18n:** `@nuxtjs/i18n` — locales in `i18n/app/locales/`: `en.json`, `cs.json`, `de.json`, `fr.json`, `es.json`. Default `en`, no-prefix strategy. Locale-aware `Intl` formatting centralised via the `INTL_LOCALE_MAP` in `App/LocalClock.vue`. Command palette exposes one "switch to <lang>" action per non-active locale. **Locale codes are exported as a single union (`LocaleCode`) from `app/types/i18n.ts`** — always use this type when narrowing/casting `setLocale` input; never inline the `'en' | 'cs' | …` union in components.
- **Backend:** Nuxt API routes + Prisma (`prisma/schema.prisma`)
- **Runtime config:** Public contact email lives in `runtimeConfig.public.contactEmail` (nuxt.config.ts), overridable via `NUXT_PUBLIC_CONTACT_EMAIL`. Read it via `useRuntimeConfig().public.contactEmail` — single source of truth used by `app/app.vue` (JSON-LD `email`), `Home/Contact.vue`, `App/Footer.vue`, and `App/CommandPalette.vue`. Never hardcode the address in components.

## Directory Structure

### Root

- `content.config.ts`: Configuration for Nuxt Content, parsing markdown files from local `content/` directory.
- `app/app.vue`: Global SEO + JSON-LD structured data via `useSchemaOrg` (`definePerson` with phone/email/sameAs/address, `defineWebSite`, `defineWebPage`) — emitted on every page through `@nuxtjs/seo` (nuxt-schema-org).

### `/pages`

- `index.vue`: The main entry point and single-page portfolio layout.
- **`blog/`**
  - `index.vue`: Lists all parsed blog posts from the local content directory.
  - `[...slug].vue`: Dynamically renders individual markdown posts using `<ContentRenderer>` and includes a sticky `TableOfContents` on desktop layouts.

### `/layouts`

- `default.vue`: Main layout wrapping the pages.

### `/components`

- **`App/`**
  - `Header.vue`: Main navigation header. Desktop nav uses a **text-first** pattern — Fraunces/Inter-friendly labels with `text-base font-medium tracking-tight`; the icon (Lucide stroke) slides in from the left only on `:hover` or `[data-active]` (scroll-spy active section). Underline is a separate scale-x layer in `primary-500` (light) / `primary-300` (dark), independent of text colour for crisp transitions. Active section is shared with `SectionRail` via [[active-section-composable]] (`useActiveSection`). Search / theme / locale buttons re-skinned as 40×40 pill controls with primary-tinted hover. Icon set is **Lucide** across the whole header for stroke consistency.
  - `Footer.vue`: Site footer. **3-column RPG-cohesive layout** (`Identity / Sections / Connect`, stacked on mobile) wrapped in `group/footer` for hover-driven reveals. **Top cartouche divider** — thin primary-gradient lines flanking a `◆` glyph, echoing the hero pill. **Identity column:** `global.name`, `footer.tagline`, location + inline `<AppLocalClock>` (same component the Contact section uses — tz-diff tooltip free). **Sections column:** sitemap mini-nav over the canonical `SectionDef` list (intro / about / references / stack / blog-preview / contact); active section pulled from the shared `useActiveSection` composable, marked with a primary dot + colour swap (matches Header behaviour). **Connect column:** social links from `socialLinks` const (LinkedIn + GitHub) plus `mailto:` to the canonical public address. **Background:** a hidden **hexagonal constellation** SVG matching `IntroHero`'s hex orientation — vertices visible always, edges (`<polygon stroke-dasharray="2 4">`) revealed via `group-hover/footer:text-primary-500/55` (alpha transition, 700ms). Reduced motion: edges held at low opacity always, no transition. (The footer-local star scatter was removed when the global `App/Starfield.client.vue` shipped — see [[global-starfield]]; footer stays opaque `dark:bg-gray-950` as a thematic "landing zone" under the starfield.) **Bottom row:** copyright + a font-mono **build stamp** (`Build <commit> · <date>`) — `commit` and `date` are injected at config-evaluation time in `nuxt.config.ts` via `execSync('git rev-parse --short HEAD')` and `new Date().toISOString().slice(0, 10)`, exposed under `runtimeConfig.public.build`. When `commit !== 'dev'` the stamp becomes a link to `<repoUrl>/commit/<sha>` (rendered via `<component :is="...">` polymorphism). game-icons.net + CC BY 3.0 attribution links inline. Light/dark aware throughout (`bg-gray-50` / `bg-gray-950`). All i18n strings live under `footer.*`.
  - `LocaleSwitcher.vue`: Headless locale-switch primitive — owns *behavior* (open/close, click-outside, ESC, `setLocale`), not look. Uses `defineOptions({ inheritAttrs: false })` so fallthrough attrs (`class`, `aria-*`, listeners) land on the default trigger `<button>` via `v-bind="$attrs"` — Vue auto-merges `class` with the component's own base classes. Callers fully restyle via class props (`panelClass`, `itemClass`, `activeItemClass`, `iconClass`) and the `transition` prop (`{ enterActive, enterFrom, leaveActive, leaveTo }`); all have sensible defaults matching the header pill. The `#trigger` slot (`{ toggle, isOpen, currentLocale }`) gives total markup control for cases like the rail's 28×28 round button. `close()` is exposed via `defineExpose` for parents that need to dismiss it on visibility change (e.g. `SectionRail`). Locale codes come from the shared `LocaleCode` union in `app/types/i18n.ts` — never hardcode the literal union in components.
  - `LocalClock.vue`: Analog/digital Prague-time clock with tz-diff tooltip; uses `<NuxtTime>` for SSR-safe digital rendering.
  - `Starfield.client.vue`: Global dark-mode-only starry-fantasy backdrop, mounted once in `app.vue` (`<LazyAppStarfield v-if="isDark" hydrate-on-idle />`). **`.client.vue` suffix** — pure client render, no SSR, no hydration mismatch, free use of `Math.random()` (different scatter each load, less déjà-vu). Three composited layers: (1) two **nebula radial-gradient blobs** (violet + indigo, alpha ~0.07, blur-3xl) as atmospheric depth; (2) **SVG static field** of 40–140 stars (`Math.max(40, Math.min(140, area/18000))`), each `<circle>` with seeded base opacity exposed as `--base-opacity` CSS custom prop; CSS twinkle in **2 duration buckets** (4s ease-in-out / 7s ease-in-out, randomized delays) — no per-frame JS, compositor handles opacity animation; (3) **subtle drifting hex constellation** (sm:+ only, top-right corner, alpha 0.05, 90s linear rotation) recycling the `IntroHero` / `Footer` hex motif as a unifying design-language echo; (4) **`<canvas>` shooting-star overlay** at DPR-capped 1.5 — `rAF` runs **only** while ≥1 shooting star is active (state machine `idle → active → idle`), spawn timer self-reschedules with random 6–12s interval (× 2.5 on mobile), max 2 concurrent (1 on mobile), each star is a bright head dot + gradient tail with fade-in / fade-out curve. Tab-hidden pause via `useDocumentVisibility`. `usePreferredReducedMotion` kills all motion, static field held at base opacity. Component fades in 600ms on mount to mask hydrate-on-idle pop-in. `pointer-events-none aria-hidden="true" fixed inset-0 -z-10`. Star count + canvas resize debounced 200ms. **Architectural note:** atmospheric sections (`About`, `Projects`, `Contact`, `TechStack`) carry `dark:bg-transparent` so the starfield bleeds through; content surfaces (`Blog`, `Footer`, `AboutCard`, `Projects` experiment panel) stay opaque as "objects on the sky" — design language is *atmosphere vs. objects*, not uniform overlay.
  - `SectionRail.vue`: Fixed vertical anchor rail. Uses the shared `useActiveSection` composable (see `app/composables/useActiveSection.ts`) for scroll-spy — same source of truth as `Header.vue`. (lg+ only, home route only). Tracks the active section with `useIntersectionObserver`, page progress with `useScroll`, idle auto-hide with `useIdle`, and `Alt+↑/↓` jump via `useMagicKeys`. Lazy-mounted in `app.vue` and gated to `/`. Hosts a compact **locale quick-action button** above the section dots — renders `<AppLocaleSwitcher>` with a `#trigger` slot for the 28×28 round button and passes rail-specific `panelClass` / `itemClass` / `activeItemClass` / `transition` props (no duplicated popover/click-outside/ESC/setLocale logic, no `variant` enum coupling the primitive to its callers). On visibility loss the parent calls `localeSwitcherRef.value?.close()`.
- **`Home/`**
  - `Intro.vue`: Hero/intro section. Two-column layout with **layered compose-style entrance**: status chip (RPG-style cartouche — bracketed `game-icons:rune-stone` glyph framing the availability label with `animate-rune-glow`, corner accents + double top/bottom lines with traveling `animate-cartouche-shimmer` gradient, role accent in `font-serif italic` separated by a diamond glyph) blur-drops in, H1 reveals **character-by-character** (each glyph y-drop + rotateX + blur-clear via GSAP stagger), subtitle reveals **word-by-word** (y-shift + blur-clear, 35ms stagger), CTA pops with scale-bounce, scroll hint fades in last. CTA is a primary-filled button bracketed by `game-icons:scroll-quill` (rotates -12° on hover) and `lucide:arrow-right` (slides right). Microcopy below CTA shows `intro.ctaSub`. Radial backdrop blobs `-z-0` plus a vignette gradient overlay. Bottom scroll hint uses `lucide:chevrons-down` with `animate-chevron-drift` keyframe; opacity + Y-translate are continuously driven by `useWindowScroll` progress (0 → 1 over first 160px), revealed via a `tl.call` flag after intro timeline. Honors `usePreferredReducedMotion` — entire timeline short-circuits to `gsap.set` final state.
  - `IntroHero.vue`: D&D-themed hero composition (replaces old `CanvasGlobe`). Pure SVG + Iconify, no Three.js. **Compose-style assembly** orchestrated by a GSAP timeline:
    1. Halo blooms in (scale 0.4 → 1)
    2. Outer ring **stroke-draws** via `strokeDashoffset` (1.4s `power2.inOut`), then its dashed companion fills in
    3. **24 tick marks** appear one-by-one in rotation around the dial (40ms stagger)
    4. **6 hex edges** inscribe **sequentially** via per-edge `strokeDashoffset` draw (120ms stagger) with `feGaussianBlur` soft-glow filter
    5. Inner dashed hex zooms in from 1.4x
    6. Inner counter-rotating ring stroke-draws
    7. **6 energy lines** from center to each rune vertex draw + settle to low ambient opacity
    8. Each rune position gets a **radial flash burst** (expanding `<circle>` with radial gradient) just before the rune appears
    9. **Runes materialize** with back-out scale (90ms stagger)
    10. **D20 summons** with rotateZ -540° → 0 + scale 0.2 → 1 (back-out), and a **shockwave ring** expands outward (radius 18 → 95)
    11. 18 ambient particles orbiting the perimeter twinkle in with random delays and continue yo-yo opacity loop indefinitely

    Hover on hero brightens the energy lines (0.12 → 0.4 opacity). Hovering or clicking the d20 triggers a **two-phase roll** (fast 720° in 0.55s `power2.in`, then settle with back-out + 1.1 → 1 scale) and a fresh shockwave. The entire composition has subtle **3D cursor parallax** (rotateX/rotateY based on `useMouseInElement`, max ±4-5°, `[transform-style:preserve-3d]` + `[perspective:1200px]`). Mount waits on `useElementVisibility` so the timeline only fires when the section is on screen. All colors are `text-primary-*`. Honors `usePreferredReducedMotion` — when reduced, `composeScene` short-circuits to `gsap.set` final state (no timeline, no tilt, no roll). Idle keyframes (`spin-slow`, `spin-slow-reverse`, `rune-float`, `aura-pulse`, `scroll-dot`, `chevron-drift`, `cartouche-shimmer`, `rune-glow`) live in `nuxt.config.ts` tailwind theme.

  - `AboutFactCard.vue`: Polished fact card with shared chrome (mouse-tracked spotlight, accent rail, colored hover shadow) and per-fact micro-details: **learning** → animated sparkline (`stroke-dashoffset` on hover) + SMIL-pulsing end-dot; **lifestyle** → dumbbell with hover micro-rotation; **rpg** → inline SVG d20 with rolling face on hover (settles on natural 20) + rune watermark.
  - `Projects.vue`: Project showcase **shell** — owns timeline layout, alternating left/right rail, GSAP scrollTrigger entrance animations, and the data arrays (`productionProjects` + `experimentProjects`). A `timelineEntries` computed flattens both into a single render list with a section-header entry injected between them. The header carries the R&D / Hackathons / AI Experiments kicker + disclaimer (`projects.experiments.*`). Outer container is `max-w-6xl` (widened from 4xl) so each alternating half-column gives cards room to breathe on desktop; the experiment header stays centered-narrow via its own `md:max-w-2xl`. Card rendering is delegated entirely to `HomeProjectCard`; this file no longer owns tech-icon maps, category styles, or status pill logic. Shared `Project` / `ProjectTech` / `ProjectStatus` / `ProjectKind` / `TechCategory` types live in `app/types/project.ts`.
  - `ProjectCard.vue`: Wrapper card for a single project on the timeline. **A11y:** `<article aria-labelledby>` with `useId()`-generated title id, semantic `<dl>` for tech-stack groups, all decorative icons `aria-hidden`, external `NuxtLink` gets `rel="noopener noreferrer"` + composed `aria-label` ("Live Demo — {project} ({opensNewTab})"). **Uniform height:** every card shares a fixed `min-h-[33rem] lg:min-h-[35rem]`; the meta-row + tech block are pushed to the bottom via `mt-auto`, so cards line up regardless of content length. **Overflow strategy (inline collapsible):** description clips via animated `max-height` (`4.5rem` → `lg:6.5rem` closed, `40rem` open) with `transition-[max-height]` + a bottom fade `mask-image` (applied only while clipped & closed), driven by a measured "Show more / Show less" toggle (overflow detected via `useResizeObserver` comparing `scrollHeight`/`clientHeight`, gated while open). Tech stack shows the **first two present categories** as preview; any remaining categories collapse into a Reka UI `CollapsibleRoot`/`CollapsibleContent`/`CollapsibleTrigger` (`reka-ui`, imported directly — not a Nuxt module). Trigger label uses `projects.moreTech` ({count} = remaining tech count) ↔ `projects.showLess`. Collapse height animation via Tailwind `animate-collapsible-down/up` keyframes (driven by `--reka-collapsible-content-height`, defined in `nuxt.config.ts`); Reka presence handles actual mount/unmount so `motion-reduce:animate-none` degrades to an instant show/hide. All toggles use VueUse `useToggle` (explicit import — `@vueuse/nuxt` is not registered, so VueUse is imported from `@vueuse/core` per project convention). **Background:** accent-tinted via `--card-glow` CSS var (sky for production, violet for experiment) — a static blurred top-right radial + a cursor-following spotlight radial (`useMouseInElement` → `--spot-x/--spot-y`, revealed on `group-hover/card`, hidden under `motion-reduce`). **Responsive:** image `h-52 lg:h-64 object-cover`, content padding/gap scale `p-5 sm:p-6 lg:p-8` / `gap-4 lg:gap-6`, title `text-xl md:text-2xl lg:text-[1.75rem]`. **Dark/light:** light = `bg-white/90` + soft slate shadow; dark = `bg-gray-900/70` + `backdrop-blur-sm` (opaque enough to sit cleanly on the starfield without contrast loss). Experiment variant overrides border (`border-violet-200/70 dark:border-violet-400/25`), background tint (`dark:bg-violet-950/30`), and adds a top-edge violet hairline gradient. **Hover/focus-within:** card lifts (`-translate-y-1`), shadow intensifies, border darkens, internal image scales `1.03`. All motion gated via `motion-reduce:*`. Owns the `STATUS_STYLES` / `STATUS_DOT` / `CATEGORY_STYLES` / `TECH_ICONS` constants (not shared — visual concerns, not data).

- **`Blog/`**
  - `TableOfContents.vue`: A sticky table of contents navigation component for blog articles.
- **`Contact/`**
  - `Form.vue`: Contact form. **Validation is shared with the server** — single Zod schema imported from `~~/shared/contact-schema.ts` (`contactFormSchema`, `CONTACT_REASONS`, `ContactFormField`). State is held in three flat `shallowReactive` objects (`form`, `errors`, `touched`) — no `.value` indirection, top-level key mutations are exactly what the v-model / lookup pattern needs. `isConsentOpen` uses VueUse's `useToggle` (returns `[ref, setter]`). Per-field state machine: each field tracks `touched` and `errors` independently; `validateField` runs `contactFormSchema.shape[field].safeParse(form[field])` on `@blur` (first touch) and on every `@input` thereafter, so a field never flashes red on first focus but corrects live once the user is engaged. On submit, the full schema is `safeParse`d; on failure all offending fields are forced `touched=true` and the parent toast fires `contact.errors.formInvalid`. Errors render inline below each field with `lucide:alert-triangle` + rose-tinted border and a `<Transition>` (opacity + -translate-y-1, 200/150ms), `aria-invalid` + `aria-describedby` wired per field. Native `required` attributes were removed — Zod is the single source of validation truth. Error messages live under `contact.errors.*` (CS/EN) in a warm conversational first-person voice ("Pověz mi své jméno — alespoň 2 znaky.", "I'll need your consent to reply.", …) — friendlier than generic SaaS strings, but tonedown from full RPG metaphor. The hidden honeypot `website` field remains, checked server-side before schema parsing. Reset uses `Object.assign(form, emptyForm())` + a `clearKeys` helper (assigns `undefined`, never `delete` — keeps `@typescript-eslint/no-dynamic-delete` happy).
  - `Consent.vue`: Privacy/consent checkbox component.

### `/shared`

- `contact-schema.ts`: Single Zod schema (`contactFormSchema`) + `CONTACT_REASONS` tuple + `ContactFormInput` / `ContactFormField` types. Imported by both `app/components/Contact/Form.vue` (client-side per-field validation) and `server/api/contact.ts` (server-side payload check) via the `~~/shared/...` alias — there is no duplicated validation logic between client and server.

### `/server`

- **`api/`**
  - `contact.ts`: Endpoint for handling contact form submissions. Imports `contactFormSchema` from `~~/shared/contact-schema.ts` — same schema the client uses. Checks the `website` honeypot first, then `safeParse`s the body; on failure returns `{ status: 400, error: <code> }` (codes match keys under `contact.errors.*` in the i18n dictionaries). Sanitises the parsed payload with `validator.escape` + `normalizeEmail`, persists via ZenStack v3 (`contactSubmission.create`), then dispatches via `nuxt-nodemailer`. Server-only errors (`email_failed`, `server_error`) also live under `contact.errors.*`.
