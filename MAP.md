# Project Map

This file documents the structure and key components of the Nuxt 4 portfolio project. **Every structural change or new functionality added MUST be documented here.**

## Core Setup

- **Framework:** Nuxt 4 + Vue 3 + TypeScript
- **Styling:** Tailwind CSS + SCSS (`assets/scss/base.scss`)
- **Typography:** `@nuxt/fonts` self-hosts **Geist** (display + body sans, full weight range) and **Geist Mono** (code). Global type scale lives in `nuxt.config.ts` under `tailwindcss.config.theme.extend.fontSize` as fluid `clamp()` tuples with `lineHeight` + `letterSpacing`. Display sizes use the `text-d-*` utilities (`d-xs`…`d-2xl`). Body defaults to `font-sans`; headings auto-apply `font-display font-semibold tracking-tight` + `text-wrap: balance` via `@layer base` in `base.scss` (H1 is `font-bold`). Section rhythm tokens: `p-section-y`, `p-section-x`, `gap-gutter`; content widths: `max-w-prose`, `max-w-content`. Title + subtitle pairs use a `<header>` wrapper (single external `mb-*`, internal `mt-3` between H2 and `<p>`) — applied in `TechStack.vue` and `Contact.vue`.
- **Toolchain:** **Bun** is the package manager (`bun.lock`, `bunfig.toml` — `hoisted` linker), script runner, and production runtime. **Vite stays as the build-time bundler** (it is inseparable from Nuxt; `bun build` cannot bundle a Nuxt app). Deployment target is **Vercel** (Nitro auto-detects the `vercel` preset — do **not** set `preset: 'bun'`, it breaks on Vercel). Serverless functions run on the **Bun runtime** via `nitro.vercel.functions.runtime = 'bun1.x'` in `nuxt.config.ts`; Vercel also auto-uses `bun install` when it sees `bun.lock`. **`@nuxt/content` uses the `postgresql` connector** (`content.database` in `nuxt.config.ts`) over the existing `pg` + `DATABASE_URL` — the same Postgres the contact form / ZenStack already require. This deliberately removes `better-sqlite3`, whose native build fails under Bun's install sandbox; content now ships zero native DB modules. Remaining native modules that compile during install (`@takumi-rs/core`, `sharp`, `esbuild`, `@parcel/watcher`) are whitelisted under `trustedDependencies` in `package.json`, otherwise Bun skips their lifecycle scripts. Vue version pinning moved from `pnpm.overrides` to top-level `overrides`. CI (`.github/actions/setup`) uses `oven-sh/setup-bun`; all jobs run `bun`/`bunx`.
- **State:** Pinia (`stores/theme.ts`)
- **i18n:** `@nuxtjs/i18n` — locales in `i18n/app/locales/`: `en.json`, `cs.json`, `de.json`, `fr.json`, `es.json`. Default `en`, **`prefix_except_default` strategy** — `en` stays at `/`, every other locale is prefixed (`/de/…`, `/fr/…`). `baseUrl` is set in `nuxt.config.ts` so `@nuxtjs/i18n` can emit fully-qualified `hreflang` alternates; it must stay in sync with `site.url`. **Consequence for links:** a plain `<NuxtLink to="/blog">` does *not* carry the locale prefix and silently drops the visitor back to `en` — internal absolute paths must use `<NuxtLinkLocale>` (or `localePath()` in script, as `App/CommandPalette.vue` does). Hash-only anchors (`#contact`) and external URLs stay on plain `<NuxtLink>`. Locale-aware `Intl` formatting centralised in `app/consts/intl.ts` — `INTL_LOCALE_MAP` (`LocaleCode` → BCP-47 tag) + the `toIntlLocale()` helper, auto-imported through `imports.dirs: ['~/consts']` and consumed by `App/LocalClock.vue` and `Home/GithubActivity.vue`. Never re-declare the map inside a component. Command palette exposes one "switch to <lang>" action per non-active locale. **Locale codes are exported as a single union (`LocaleCode`) from `app/types/i18n.ts`** — always use this type when narrowing/casting `setLocale` input; never inline the `'en' | 'cs' | …` union in components.
- **Backend:** Nuxt API routes + Prisma (`prisma/schema.prisma`)
- **Runtime config:** Public contact email lives in `runtimeConfig.public.contactEmail` (nuxt.config.ts), overridable via `NUXT_PUBLIC_CONTACT_EMAIL`. Read it via `useRuntimeConfig().public.contactEmail` — single source of truth used by `app/app.vue` (JSON-LD `email`), `Home/Contact.vue`, `App/Footer.vue`, and `App/CommandPalette.vue`. Never hardcode the address in components. The GitHub activity section adds `runtimeConfig.githubToken` (**private**, `NUXT_GITHUB_TOKEN`, server-only — a classic PAT with the single `read:user` scope — repo/star/language data is all public, so no `repo` scope is needed; the contribution calendar has no unauthenticated GraphQL equivalent) and `runtimeConfig.public.github.username` (`NUXT_PUBLIC_GITHUB_USERNAME`, defaults to `bigjohnn1`) used by both the API route and the section's profile links.

## Directory Structure

### Root

- `content.config.ts`: Configuration for Nuxt Content, parsing markdown files from local `content/` directory. The `blog` collection schema declares `cover`, `date`, `tags`. **Gotcha:** any field declared in the schema becomes its own column and is exposed **top-level** on query results (`post.cover`) — `post.meta` is only the catch-all bucket for frontmatter keys *not* in the schema. Reading a declared field off `meta` silently yields `undefined`, so add the field to the schema *and* read it top-level, or leave it out of both.
- `app/app.vue`: Global SEO + JSON-LD structured data via `useSchemaOrg` (`definePerson` with phone/email/sameAs/address, `defineWebSite`, `defineWebPage`) — emitted on every page through `@nuxtjs/seo` (nuxt-schema-org).

### `/pages`

- `index.vue`: The main entry point and single-page portfolio layout.
- **`blog/`**
  - `index.vue`: Lists all parsed blog posts from the local content directory.
  - `[...slug].vue`: Dynamically renders individual markdown posts using `<ContentRenderer>` and includes a sticky `TableOfContents` on desktop layouts. **The content path is rebuilt from `route.params.slug`, never from `route.path`** — under `prefix_except_default` the live URL is `/cs/blog/foo` while the content collection stores `/blog/foo`, so querying by `route.path` 404s on every non-`en` locale. **Code blocks:** Nuxt Content ships Shiki dual themes (`github-light` / `github-dark`) and injects its own `<style>` painting tokens via `--shiki-default` / `--shiki-dark`. `@tailwindcss/typography` styles `pre` with a *dark* background in **both** modes, which put near-black `github-light` tokens on a near-black block. The `article` therefore overrides `pre` per mode with `[&_pre]:*` arbitrary variants (specificity beats the plugin's `:where()` rules, so no `!important` and no layer-order guessing) — light block in light mode, dark block in dark mode. The `text-*` half is not cosmetic: untokenized spans resolve `var(--shiki-default)` to nothing and fall back to the inherited `pre` colour.

### `/layouts`

- `default.vue`: Main layout wrapping the pages.

When `commit !== 'dev'` the stamp becomes a link to `<repoUrl>/commit/<sha>` (rendered via `<component :is="...">` polymorphism). game-icons.net + CC BY 3.0 attribution links inline. Light/dark aware throughout (`bg-gray-50` / `bg-gray-950`). All i18n strings live under `footer.*`.

Uses `defineOptions({ inheritAttrs: false })` so fallthrough attrs (`class`, `aria-*`, listeners) land on the default trigger `<button>` via `v-bind="$attrs"` — Vue auto-merges `class` with the component's own base classes. Callers fully restyle via class props (`panelClass`, `itemClass`, `activeItemClass`, `iconClass`) and the `transition` prop (`{ enterActive, enterFrom, leaveActive, leaveTo }`); all have sensible defaults matching the header pill. The `#trigger` slot (`{ toggle, isOpen, currentLocale }`) gives total markup control for cases like the rail's 28×28 round button. `close()` is exposed via `defineExpose` for parents that need to dismiss it on visibility change (e.g. `SectionRail`). Locale codes come from the shared `LocaleCode` union in `app/types/i18n.ts` — never hardcode the literal union in components.

  - `Starfield.client.vue`: Global dark-mode-only starry-fantasy backdrop, mounted once in `app.vue` (`<LazyAppStarfield v-if="isDark" hydrate-on-idle />`). **`.client.vue` suffix** — pure client render, no SSR, no hydration mismatch, free use of `Math.random()` (different scatter each load, less déjà-vu). Three composited layers: (1) two **nebula radial-gradient blobs** (violet + indigo, alpha ~0.07, blur-3xl) as atmospheric depth; (2) **SVG static field** of 40–140 stars (`Math.max(40, Math.min(140, area/18000))`), each `<circle>` with seeded base opacity exposed as `--base-opacity` CSS custom prop; CSS twinkle in **2 duration buckets** (4s ease-in-out / 7s ease-in-out, randomized delays) — no per-frame JS, compositor handles opacity animation; (3) **subtle drifting hex constellation** (sm:+ only, top-right corner, alpha 0.05, 90s linear rotation) recycling the `IntroHero` / `Footer` hex motif as a unifying design-language echo; (4) **`<canvas>` shooting-star overlay** at DPR-capped 1.5 — `rAF` runs **only** while ≥1 shooting star is active (state machine `idle → active → idle`), spawn timer self-reschedules with random 6–12s interval (× 2.5 on mobile), max 2 concurrent (1 on mobile), each star is a bright head dot + gradient tail with fade-in / fade-out curve. Tab-hidden pause via `useDocumentVisibility`. `usePreferredReducedMotion` kills all motion, static field held at base opacity. Component fades in 600ms on mount to mask hydrate-on-idle pop-in. `pointer-events-none aria-hidden="true" fixed inset-0 -z-10`. Star count + canvas resize debounced 200ms. **Architectural note:** atmospheric sections (`About`, `Projects`, `Contact`, `TechStack`) carry `dark:bg-transparent` so the starfield bleeds through; content surfaces (`Blog`, `Footer`, `AboutCard`, `Projects` experiment panel) stay opaque as "objects on the sky" — design language is *atmosphere vs. objects*, not uniform overlay.
  - `SectionRail.vue`: Fixed vertical anchor rail. Uses the shared `useActiveSection` composable (see `app/composables/useActiveSection.ts`) for scroll-spy — same source of truth as `Header.vue`. (lg+ only, home route only). Both the active dot **and** the line-fill progress come from `useActiveSection` (single source of truth, so they can never disagree): it picks the last section whose `top` has crossed a line at 40% of viewport height (`activeId`), and derives `progress` as `(index + within) / (count - 1)` where `within` is how far the detection line has travelled through the current section toward the next. Because the dots are evenly spaced, this lands the fill's leading edge exactly on the active dot regardless of section heights. This replaced (a) a `useIntersectionObserver` band that skipped ahead past short sections like `#stack` and (b) a `useScroll` `y / max` fill that tracked global page-scroll %, which overshot the dots since sections have wildly different heights (`#references` `min-h-screen`, `#contact` `py-28`). `useScroll` (`y`, `arrivedState`) is still used for `pastIntro` / idle gating. Idle auto-hide with `useIdle`, and `Alt+↑/↓` jump via `useMagicKeys`. Lazy-mounted in `app.vue` and gated to the home route. **The gate compares `useRouteBaseName()(route)` against `'index'`, never `route.path === '/'`** — under `prefix_except_default` the home route is `/` only for `en`; `cs`/`de`/`fr`/`es` land on `/cs`, `/de`, … so a path comparison silently unmounts the rail for every non-default locale (and `detectBrowserLanguage.redirectOn: 'root'` sends most visitors straight there). Hosts a compact **locale quick-action button** above the section dots — renders `<AppLocaleSwitcher>` with a `#trigger` slot for the 28×28 round button and passes rail-specific `panelClass` / `itemClass` / `activeItemClass` / `transition` props (no duplicated popover/click-outside/ESC/setLocale logic, no `variant` enum coupling the primitive to its callers). On visibility loss the parent calls `localeSwitcherRef.value?.close()`.

    2. Outer ring **stroke-draws** via `strokeDashoffset` (1.4s `power2.inOut`), then its dashed companion fills in
    3. **24 tick marks** appear one-by-one in rotation around the dial (40ms stagger)
    4. **6 hex edges** inscribe **sequentially** via per-edge `strokeDashoffset` draw (120ms stagger) with `feGaussianBlur` soft-glow filter
    5. Inner dashed hex zooms in from 1.4x
    6. Inner counter-rotating ring stroke-draws
    7. **6 energy lines** from center to each rune vertex draw + settle to low ambient opacity
    8. Each rune position gets a **radial flash burst** (expanding `<circle>` with radial gradient) just before the rune appears
    9. **Runes materialize** with back-out scale (90ms stagger)
    10. **D20 summons** with rotateZ -540° → 0 + scale 0.2 → 1 (back-out), and a **shockwave ring** expands outward (radius 18 → 95)
    11. 18 ambient particles orbiting the perimeter twinkle in with random delays and continue yo-yo opacity loop indefinitely

    Hover on hero brightens the energy lines (0.12 → 0.4 opacity). The d20 is a real **`<button>` ("roll for fate" navigation)** — the surrounding SVG/halo/runes are `aria-hidden`, the button carries `intro.roll.aria`, is keyboard-focusable (`focus-visible` ring + glow), and `:disabled` while a roll is in flight. **Click rolls a d20 (1–20):** two-phase spin (720° in 0.55s `power2.in`, then back-out settle) + shockwave, then a **result badge** rises above the die showing `intro.roll.lead` + the number + the destination's `nav.*` label, and after a beat smooth-scrolls (`scrollIntoView`, native — no ScrollToPlugin registered) to the mapped section. `value % 4` maps across `fateDestinations` (references / stack / about / blog-preview); a **natural 20 is a crit** → gold flash burst (`critFlash`), amber "20", `intro.roll.crit` caption, and routes to `#contact` (the conversion, deliberately reserved for the crit so the roll never competes with the primary CTA). Badge centering is owned by GSAP (`xPercent: -50`) to avoid clobbering a Tailwind `-translate-x-1/2`. The composition has subtle **3D cursor parallax** (rotateX/rotateY based on `useMouseInElement`, max ±4-5°, `[transform-style:preserve-3d]` + `[perspective:1200px]`). Mount waits on `useElementVisibility` so the timeline only fires when the section is on screen. All colors are `text-primary-*` (crit accents `amber-*`). Honors `usePreferredReducedMotion` — when reduced, `composeScene` short-circuits to `gsap.set` final state and a roll skips straight to badge + instant (`behavior:'auto'`) scroll. ### `/server`

- **`api/`**
  - **`github/`**
    - `stats.get.ts`: Live GitHub activity endpoint, wrapped in `defineCachedEventHandler` (`maxAge: 15min`, `swr: true`, one fixed cache key for every visitor) so visitor traffic never maps 1:1 onto GitHub's rate limit — the token is only ever used server-side and never reaches the client. **One GraphQL v4 request** carries everything: `contributionsCollection` (calendar weeks, commit/PR/issue totals, `totalRepositoriesWithContributedCommits`) plus `commitContributionsByRepository(maxRepositories: 12)`, and from each of those repos the `languages` byte breakdown and `defaultBranchRef` `history(first: 10)` with `messageHeadline` / `oid` / `committedDate` / `url`. The owned-repos connection is queried only for the star total.
      - **Why `commitContributionsByRepository` and not the REST events feed:** the first implementation read commit messages from `/users/:login/events/public` `PushEvent` payloads. **GitHub no longer ships the `commits` array in that payload** — it now contains only `push_id` / `ref` / `head` / `before`, so the commit log always came back empty. `commitContributionsByRepository` is also the only source that sees **organisation** repos; scoping to `ownerAffiliations: OWNER` reported "2 public repos" for an account whose real work lives under org owners.
      - **Privacy:** contributed repos are filtered to `isPrivate === false` before anything is rendered, so private repo names, URLs and commit messages never reach the payload. The aggregate `contributionsCollection` counters (and therefore the calendar) still include private contributions exactly as the public GitHub profile does.
      - **Language shares are weighted by commit count, not raw bytes** — each repo contributes `commits × (languageSize / repoSize)`. A one-commit drive-by PR into a huge OSS repo would otherwise swamp the chart with that project's language; this way the split reflects where the work actually went. Top 6, and anything under 1% is dropped — a language that rounds to "0%" in the legend reads as a rendering bug, not as a fact.
      - Commits are filtered to `author.user.login === login` (the default branch also carries other people's commits), sorted by `committedDate` desc, headline clipped to 120 chars, capped at 3. `NUXT_GITHUB_TOKEN` is required (the contribution calendar has no unauthenticated equivalent) — missing token throws `503 github_token_missing`, an upstream failure throws `502`; neither gets cached, and the client renders its offline state.
  - `contact.ts`: Endpoint for handling contact form submissions. Imports `contactFormSchema` from `~~/shared/contact-schema.ts` — same schema the client uses. Checks the `website` honeypot first, then `safeParse`s the body; on failure returns `{ status: 400, error: <code> }` (codes match keys under `contact.errors.*` in the i18n dictionaries). Sanitises the parsed payload with `validator.escape` + `normalizeEmail`, persists via ZenStack v3 (`contactSubmission.create`), then dispatches via `nuxt-nodemailer`. Server-only errors (`email_failed`, `server_error`) also live under `contact.errors.*`.
